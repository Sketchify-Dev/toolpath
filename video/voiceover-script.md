# Toolpath — Voiceover Script (90-second demo film)

Tone: professional, confident, natural product engineer. Not overacted, not marketing-heavy.
Target: fits ~90 seconds. Do not speed-read to force it into 90 seconds.

---

**[0:00–0:08] Scene 01 — Hook**

Most agents don't have a tool problem. They have a context problem.

**[0:08–0:19] Scene 02 — The problem**

Before a task even begins, an agent can load dozens of tool schemas it may never use. Forty tools, twelve thousand four hundred estimated context tokens — for a task that only needs a few.

**[0:19–0:29] Scene 03 — Introducing Toolpath**

Toolpath takes a different approach. It models tools, capabilities, and entities as a graph, then resolves the path a task actually needs.

Traverse, don't preload.

**[0:29–0:41] Scene 04 — Explain the graph traversal**

A task maps to capabilities. Graph traversal identifies the matching tools. Only those tools need to enter context.

Three capabilities, three tools, one graph traversal, six hops.

**[0:41–0:64] Scene 05 — Real product demonstration**

Let's run the demo.

The baseline preloads forty tools and estimates twelve thousand four hundred context tokens. Toolpath identifies three relevant tools: repository resolution, pull request reading, and issue creation. The graph makes that selection inspectable, and the execution log shows how the task progresses.

**[0:64–0:76] Scene 06 — The numbers**

The result: one thousand eight hundred estimated context tokens instead of twelve thousand four hundred. An estimated reduction of around eighty-five percent.

**[0:76–0:84] Scene 07 — Technical honesty and value**

The deployed demonstration uses a recorded snapshot, and the token figures are reproducible estimates, not live tokenizer measurements.

Less unnecessary context. More deliberate tool selection.

**[0:84–0:90] Scene 08 — Closing**

Toolpath.

Traverse, don't preload.
